# Adaptive financing policies

Local implementation based on clean FlowSim checkout 80029d6. Fixed-share routing is preserved. The model now covers investments and margin debt only, with current household pay and portfolio distributions funding each month's obligations. No account connections, persistence or network requests are added.

The normal form groups Portfolio, Household cash flows, and Bill-financing method. Fixed share and the three adaptive policies remain available. Initial financing is shown for fixed/gradual, the increase cap only for gradual, and target only for target mode. Initial financing still defines the original-fixed-share comparison in maximum/target mode; its value is disclosed in the assumptions summary. Forecast growth, inflation, interest-payment alternatives and stress inputs live in one collapsed section, with a live active-assumptions summary outside it. Precision is automatic.

- Gradual preserves the existing initial ceiling and subsequent previous-actual-financing plus monthly-increase ceiling.
- Maximum searches through the current month's bills without a ramp.
- Target uses the same unrestricted bill ceiling, but also caps actual borrowing-peak DTA at the entered target. This operating aim is distinct from the stressed hard DTA screen. It is measured after opening shocks, new bill financing and actual capitalized interest, before price growth, contributions or repayments; separate cash is excluded. Target must be between zero and the hard DTA guardrail. Existing debt above target pauses new financing; normal funded distributions/cash may repay debt. The model neither borrows beyond actual bills nor invents repayment to hit a ratio.

Every policy retains stressed opening collateral, stressed peak debt (including stressed capitalized interest), stressed interest-only coverage and current household-funding checks. Additional haircut, payout reduction and rate stresses still compound selected path shocks. Undefined ratios do not pass.

Safety Buffer B2 is removed, not set to a zero household balance. No separate cash balance is accepted, carried forward, used for shortfalls, or added to equity. Net equity is investments minus margin debt. Available monthly funds follow the investment/paydown waterfall; remaining funds are invested. A funding gap stops that path and is recorded as funding_shortfall in the ledger/CSV. Failed-month balances are investment/debt snapshots, not a complete household balance sheet: unpaid obligations are reported separately and no equal-horizon advantage is shown.

Backward compatibility: omitted legacy cash fields work; explicit zero initial_cash, zero reserve_floor and shortfall_policy='stop' are accepted and stripped from canonical inputs. Nonzero or null legacy cash, nonzero reserve floors, cash-access shocks, reserve-funded or asset-sale shortfall policies, and cash guardrails fail explicitly. They are never silently retained, transferred to investments, or used to produce an apparently funded path. Historical reserve-dependent reference fixtures remain only as rejection evidence; completed investment-only fixtures retain accounting parity.

Automatic precision selects the highest feasible whole-dollar candidate, additionally considering the bill/ramp ceiling rounded down to cents. All selected amounts are rechecked by the original admission screens. This is within one dollar of the continuous feasible maximum when the candidate set contains a feasible amount. A sub-dollar feasible interval containing neither an integer nor the cent-rounded ceiling remains unselected; zero is still checked and never certified if it fails. Legacy grid_dollars values are ignored, and the UI no longer creates them.

The algorithm uses the current model's math, not an assumed monotone pass/fail predicate. Stressed DTA, coverage with positive interest, target DTA, and cash funding each define an affine half-line in borrowing. Their intersection is a single interval (possibly empty), with zero-interest undefined excluded. Funding can impose a lower bound; at unusually high cash-paid APR it imposes an upper bound. Disconnected feasible regions cannot arise under these equations. The engine solves upper bounds, checks the cent-rounded ceiling and adjacent integer candidates with the original predicates, and rejects unsupported numeric ranges explicitly. There is no coarse sampling, binary search, or candidate-count truncation. Monthly amounts/rates above 1 trillion fail explicitly. Future nonlinear admission screens must revisit this proof and exhaustive-oracle tests rather than reuse the solver blindly.

Rows record policy, target, actual admission peak DTA, admission pass/failure, stressed metrics and routing reasons. Admission failures are separate from actual path guardrail violations. A zero-financing month whose inherited stressed DTA exceeds the limit now appears as a warning in summary, ledger and timeline even if the unstressed path ratio is below the guardrail. Target misses are operating-aim failures, not necessarily hard-guardrail breaches. Fixed and pay-cash comparison rows have no admission result.

CSV schema 5 removes cash-balance inputs/columns and reserve metadata, adds funding_shortfall, labels target ratios with `_pct`, and retains canonical configuration JSON. Engine configurations without a mode continue to mean gradual. Results summarize month-one direct/financed bills, total contributions invested, debt, equity and the routing constraint; detailed ledger and timeline remain available below.

Verification uses synthetic inputs only. Run the engine suite with `node --test --test-isolation=none tests/flowsim*.test.js` (single process on restricted Windows environments). DOM tests use jsdom and run sequentially, including `node tests/flowsim-routing-modes-dom.cjs`. No browser preview or personal scenario is embedded in these tests. Target/maximum modes optimize current-month bill financing under the specified screens, not terminal wealth, real lender capacity or household safety.
